# ADR-0004: Payment ที่มาหลังออเดอร์หมดอายุ

**สถานะ:** ใช้งาน

## ปัญหา

`payment.succeeded` อาจมาถึงหลังออเดอร์ `EXPIRED` ไปแล้วและคืน stock ไปแล้ว เช่น provider ส่ง webhook ช้า โจทย์สั่งว่าถ้ายังมี stock ให้จองใหม่แล้วทำต่อ ถ้าไม่มีต้อง refund อัตโนมัติ แต่แผนภาพสถานะไม่มีเส้นทางนี้

## การตัดสินใจ

เพิ่ม 2 เส้นในตารางสถานะ คือ `EXPIRED → PAID` และ `EXPIRED → REFUNDED` เส้นอื่นที่เพิ่มคือ `FAILED → IN_QUEUE` และทางออกจาก `NEEDS_REVIEW` เพราะ API `retry-fulfillment` ต้องมีทางกลับเข้าคิว

ลำดับเมื่อ webhook มาถึง (ถือ lock แถวออเดอร์ตลอด จึงไม่ชนกับตัวตั้งเวลาหมดอายุ)

1. บันทึกเงินเข้า ledger ก่อนเสมอ
2. ยอดไม่ตรง ไป `NEEDS_REVIEW`
3. จอง stock, โควตาอีเมล และโค้ดส่วนลดใหม่แบบทั้งหมดหรือไม่เลยใน savepoint
4. จองได้ เดินต่อ `PAID`, `IN_QUEUE`
5. จองไม่ได้ สร้าง refund เต็มจำนวนและไป `REFUNDED`

## กรณีขอบที่โจทย์ไม่ได้ระบุ

| กรณี | ตัดสินใจ | เหตุผล |
|---|---|---|
| โค้ดส่วนลดถูกใช้เต็มแล้ว | refund | ห้ามเกินสิทธิ์ ตาม invariant ข้อ 4 |
| `payment.succeeded` หลัง `PAYMENT_FAILED` | `NEEDS_REVIEW` | ไม่มีเส้นกลับ และเป็นเงินจริงที่ต้องมีคนดู |
| เงินเข้าครั้งที่สองด้วย `event_id` ใหม่ | บันทึกยอดแล้ว `NEEDS_REVIEW` | เก็บเงียบไม่ได้ และ finance คืนส่วนเกินได้ |
| ไม่พบออเดอร์ | ตอบ 200 และเก็บ event | ไม่ให้ provider ยิงซ้ำไม่จบ และโผล่ใน reconciliation |
